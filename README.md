# موسوعة سير أعلام النبلاء

**النشر على Coolify وVPS بذاكرة 2GB:** اتبع [دليل النشر والإعداد الأول والنسخ والاستعادة](docs/DEPLOYMENT.md). فرع `main` للشيفرة؛ فرع `production` يصدر تلقائيًا بعد نجاح بناء صور GHCR الخاصة واختبارات الحاويات، ويحتوي Compose ببصمات صور ثابتة. لا تنشر علامة `unreleased` الموجودة على فرع الشيفرة.

تطبيق ويب عربي RTL يعمل محليًا للبحث الموثق في النص الأصلي: فهرس التراجم والأعلام، الموضوعات وشواهدها، قراءة النص كاملًا، ومواضع ذكر الأشخاص، مع مراجعة بشرية وسجل للتعديلات. لا يحتاج مفاتيح API أو خدمة مدفوعة، ولا يولّد نصوصًا أو إحالات.

البنية: **FastAPI + Python، SQLite/FTS5، React + TypeScript + Vite**. الخطوط مضمنة محليًا؛ لا تعتمد القراءة على خدمة خطوط خارجية.

نُشر تحديث التشكيل الكامل والترتيب السياقي للتراجم **1–10** بطلب صريح في 28 أكتوبر 2026، مع بقاء الأصل والموضوعات والمراجعات كما كانت. فُحصت 23,024 كلمة؛ بقي 126 موضعًا على ضبط المصدر مع أسباب للمراجعة. انظر [تقرير التسليم والاختبارات والصور](docs/FIRST_TEN_READING_QA.md)، و[إثبات الحفظ المستقل](docs/FIRST_TEN_READING_INTEGRITY.json). التشكيل إضافة تحريرية يمكن تعطيلها داخل القارئ.

## مهارة معالجة دفعات التراجم

عند طلب تحديث تراجم **منشورة** صراحة، تستخدم المهارة مسار تصحيح القراءة الذي يحفظ نسختها السابقة وموضوعاتها ومراجعاتها:

```powershell
python -m backend.reading_revision export --start 1 --end 2
python -m backend.reading_revision status --batch "<مسار التصحيح>"
python -m backend.reading_revision validate --batch "<مسار التصحيح>" --authoring-only
python -m backend.reading_revision validate --batch "<مسار التصحيح>"
python -m backend.reading_revision preview --batch "<مسار التصحيح>"
python -m backend.reading_revision publish --batch "<مسار التصحيح>"
```

هذه أوامر إعداد وفحص ونشر طبقة القراءة؛ لا تؤلف التشكيل لغويًا بنفسها. يملأ الوكيل النص والتعليلات، ثم يدققها قارئ مستقل وتُختبر المعاينة. النطاق الداخلي الأقصى خمس تراجم، ويُرفض تعارض لقطة الطبقة الحالية. يحفظ `reading_revision_history` الصفوف السابقة كاملة مع المؤلف والمدقق وسبب التعديل؛ لا تتغير دفعات الموضوعات أو قرارات الإنسان. تفاصيل العقد في [تصحيح القراءة المنشورة](.agents/skills/siyar-biography-curation/references/published-reading.md).

بعد النشر، يتحقق مدقق مستقل من الحفظ والتاريخ:

```powershell
python scripts/audit_reading_revision.py --db data/library.sqlite3 --baseline "<احتياطي الناشر>" --biography-ids 1 2 --source data/source.mARkdown --output "<مجلد التصحيح>/integrity.json"
```

تُلزم النسخة الجديدة الدفعات المستقبلية بالتشكيل الكامل، بما فيه أواخر الكلمات بحسب السياق، وتعليل حدود الفقرات بعد قراءة الأخبار والأسانيد والحوار. تحفظ حركات المصدر كما هي، وتخزن الحركات المضافة في طبقة مستقلة؛ ويُترك الموضع الملتبس على ضبط المصدر مع سبب ظاهر ومراجعة مستقلة. لا يتغير النص المرجعي أو نص الشاهد بسبب التشكيل.

تُصدر الدفعات الجديدة بصيغة `curation-batch-v2` مع `diacritics.json` وسجل مراجعة كل كلمة، وأسباب الفقرات `paragraph_notes`. يجب أن تحمل الكلمة المعلنة مكتملة الضبط حركة أصلية أو مضافة على الأقل؛ هذا فحص للسهو الكامل، أما صحة الصرف والإعراب واكتمالهما فتحتاج القراءة والتدقيق اللغوي. تعرض الواجهة التشكيل افتراضيًا مع خيار محفوظ «إظهار الحركات المضافة». إطفاؤه يبقي حركات المصدر الأصلية، ويطابق النسخ المنسق الخيار الحالي مع تنبيهه التحريري. تبقى سياقات ملحق الحواشي حرفية، ويظل نسخ الأصل مستقلًا.

لا يُعاد تحرير الدفعات المنشورة، ومنها الخمس الأولى، تلقائيًا. لترقية **مساحة عمل قديمة غير منشورة** فقط:

```powershell
python -m backend.curation upgrade --batch "<مسار دفعة v1 غير المنشورة>"
```

يحفظ الأمر نسخة من المجلد الأصلي، ويضيف ملف التشكيل بحالات غير مفحوصة وأسباب فقرات تنتظر التأليف، ويبطل التدقيق والمعاينة وQA السابقين؛ لا يمنحها نجاحًا تلقائيًا. تُحفظ الدفعات القديمة `v1` المنشورة ببصماتها وتظل قابلة للقراءة. تفاصيل التأليف في [مرجع التشكيل](.agents/skills/siyar-biography-curation/references/diacritization.md)، ونتائج التحقق في [تقرير التشكيل والسياق](docs/DIACRITICS_QA.md).

توجد مهارة المشروع [siyar-biography-curation](.agents/skills/siyar-biography-curation/SKILL.md). استدعها في محادثة داخل هذا المشروع، مثل:

```text
استخدم $siyar-biography-curation لمعالجة التراجم من 6 إلى 10.
```

الأرقام تعني **ترتيب التراجم المتسلسل في فهرس المصدر** (`biographies.source_ordinal`)، وليس رقم العنوان المطبوع الذي يتكرر، ولا معرّف SQLite. تعرض المهارة العناوين والحدود المحلولة، وتقسم النطاق الكبير إلى دفعات داخلية لا تتجاوز خمس تراجم. تحفظ العينة والدفعات المنشورة وتتجاوزها عند التداخل؛ إعادة تحرير المنشور ليست استبدالًا تلقائيًا.

تغطي المهارة المنهج كاملًا: قراءة جميع المقاطع، والفقرات المتصلة، والعناوين المضافة الموسومة، والأقوال والشعر والقوائم، والأسماء بالخمري والكلمات بالبترولي والإبراز الانتقائي، وألفاظ التحقيق بتمام نفيها وقيودها، والحواشي المثبتة فقط، ومراجعة المرشحات الموضوعية واكتشاف موضوعات مستندة إلى شواهد. لا يساوي فحص الوكيل اعتماد الإنسان، ولا تنشئ المهارة اقتباسات أو هويات أو أحكامًا حديثية. تقرأ كل دفعة من مصدرها؛ لا تعمم أعداد العينة أو تحذف كل رقم بين قوسين. مثال «سنة (293)» رقم من المتن يجب أن يبقى ظاهرًا.

بعد التأليف يتولى قارئ آخر تدقيق الحدود والشواهد والسياق، ثم يُفحص العرض في قاعدة معاينة معزولة. تنشر المهارة الدفعة المحلية بعد نجاح بوابات الحفظ وQA وأخذ نسخة احتياطية؛ لا تحتاج موافقة متكررة على النطاق المأذون به، ولا تسجل اعتمادًا بشريًا باسم المستخدم. لا يشمل ذلك نشر الموقع للعامة.

أدوات المشروع التي تستخدمها المهارة (التصدير لا يصنف النص تلقائيًا):

```powershell
python -m backend.curation export --start 6 --end 10
python -m backend.curation status --batch "<مسار الدفعة الذي أعاده التصدير>"
python -m backend.curation validate --batch "<مسار الدفعة>" --authoring-only
python -m backend.curation validate --batch "<مسار الدفعة>"
python -m backend.curation preview --batch "<مسار الدفعة>"
python -m backend.curation publish --batch "<مسار الدفعة>"
```

تقبل الأوامر `--db` و`--source` لاختبار قاعدة ومصدر مستقلين، ويقبل التصدير `--work-dir`. الافتراضي `reference/curation/<بصمة المصدر>/<معرف الدفعة>/`. الملفات المصدرة تبدأ بحالات غير مفحوصة؛ تحتاج قراءة وتأليفًا فعليين. يبين `status` التغطية والمرحلة والبوابات والمتبقي وبصمات ملفات التأليف. تعديل الملفات يبطل التدقيق وQA السابقين؛ يبقى المنشور كما كان حتى ينجح نشر جديد مسموح. إعادة نشر الإصدار نفسه تعيد `unchanged`، أما الإصدار المختلف للدفعة المنشورة فيُرفض حمايةً للتاريخ.

يأخذ `preview` نسخة جديدة ولا يستبدل قاعدة المعاينة الموجودة؛ عند إعادة الفحص مرر `--output "<مسار معاينة جديد>.sqlite3"`. يعيد الأمر بيانات المعاينة وأوامر API على منفذ8001. في طرفيتين مستقلتين للمعاينة فقط:

```powershell
$env:SIYAR_DB = '<قاعدة المعاينة التي أعادتها الأداة>'
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8001
```

```powershell
$env:VITE_API_TARGET = 'http://127.0.0.1:8001'
npm --prefix frontend run dev -- --port 5174
```

المكتبة المعتادة تبقى على5173/8000؛ فتح5174 يتصل بالمعاينة. لا تحتج إلى تبديل خادم المستخدم لاختبار دفعة. تُسجل الصور الفعلية ونتائج الفحص في `qa.json` مع بصمة المعاينة؛ لا يكفي ملء علامات نجاح دون اختبار. تبقى متون الحواشي الموجودة ظاهرة، وحالة الربط الآلي غير مدعومة حاليًا؛ يسجل ذلك `present_unlinked` دون اختلاق روابط أو إخفاء المتن.

واجهات الدفعات: `GET /api/curation/batches`، ومرشح `batch_id` للمراجعة والتغطية وخطة البحث بالوصف. اختيار الدفعة يحصر الاسترجاع فيها. يظل `pilot_only` خاصًا بالعينة الأصلية، وتبقى الواجهات السابقة متوافقة. نشر دفعة جديدة يحدّث قناة الموضوعات وذاكرة البحث دون إعادة الاستيراد أو بناء المتجهات؛ لا تستخدم `backend.pilot prepare` لتوسيع النطاق.

للتحقق بعد النشر:

```powershell
python scripts/audit_curation.py --db "<قاعدة النشر>" --baseline "<نسخة الناشر الاحتياطية>" --biography-ids 6 7 8 9 10 --source data/source.mARkdown --output "<مجلد الدفعة>/integrity.json"
```

مرر في `--biography-ids` المعرفات الداخلية التي حلها البيان فعلًا؛ الأرقام في المثال تصادف ترتيب الاستيراد الحالي فقط. [تحليل المنهج](docs/CURATION_SKILL_ANALYSIS.md) و[تقرير اختبار المهارة](docs/CURATION_QA.md) يوضحان ما تم التحقق منه والقيود. لا تتطلب المهارة مهارة أخرى أو خدمة خارجية؛ إذا لم تظهر في قائمة المهارات بعد إنشاء الملفات، أعد فتح المشروع أو استدع ملف `SKILL.md` بمساره مباشرة.

لقياس استرجاع شواهد `gold.json` التي اختيرت قبل البحث وجُمّدت في المعاينة:

```powershell
python scripts/evaluate_curation.py --batch "<مسار الدفعة>" --db "<قاعدة المعاينة>" --source data/source.mARkdown --scope both --output "<مجلد الدفعة>/evaluation.json"
```

يسجل البحث العام والمحصور بالدفعة منفصلين، وحرفية النتائج، ونمط الاسترجاع الفعلي، وp95 بعد تحميل النماذج ومسح ذاكرة النتائج لكل سؤال. معيار الاسترجاع ونطاقه موضحان في [بوابات التحقق](.agents/skills/siyar-biography-curation/references/quality-gates.md)؛ أسئلة الوكلاء التطويرية لا تمثل اعتمادًا علميًا بشريًا ولا تقييمًا شاملًا للكتاب.

## تحديث فقرات القراءة وإبراز التحقيق — أول خمس تراجم

تُعرض الفقرات المتصلة دون فصل كل جملة أو كل علامة `#`، وتلتف الأسطر تلقائيًا حسب الشاشة. تبقى العناوين والقوائم والشعر مستقلة. تتضمن نسخة القراءة **433 مجموعة مصدرية** و**55 تعليقًا** لإبراز ألفاظ تقويم الأحاديث والأسانيد والأخبار كما وردت، بخط عريض وتظليل دافئ وخيار مستقل «إبراز عبارات التحقيق». ليست هذه التعليقات تصحيحًا أو تضعيفًا جديدًا؛ تحفظ النفي والتحفظ ونسبة القول وقيد المنام.

بعد إعداد تجربة الخمس بالأمر `prepare` أدناه، ثبت تحديث القراءة وحده:

```powershell
.\.venv\Scripts\python.exe -m backend.pilot prepare-reading
```

ينشر الأمر الملفات المرتبطة ببصمة المصدر من `reference/pilot-reading/` داخل الجدول المشتق المستقل `pilot_reading_overlays`، بعد التحقق من التغطية وأخذ نسخة SQLite احتياطية. تُنشر الخمس معًا؛ الإخفاق لا يستبدل نسخة سليمة جزئيًا، والتكرار يعيد `unchanged`. **لا تعِد تشغيل استيراد الكتاب أو `prepare` أو إعداد النماذج لأجل تعديل الفقرات**. يعمل تحديث القراءة حتى عند وجود مراجعات بشرية سابقة، دون تغييرها أو تغيير الفهرس الموضوعي.

تعيد واجهة `GET /api/biographies/{id}/presentation` الحقول الإضافية `presentation_revision` و`paragraph_groups` و`criticism`، ونسخة عرض مجمعة يستخدمها العرض والنسخ معًا. تظل `revision` الخاصة بالتجربة السابقة مستقلة. عند غياب التحديث أو قدم بصمته يعود العرض السابق، مع تنبيه عند القدم. النص الخام حرفي، وإشارات الحواشي الـ374 محفوظة في الملحق، والترجمة السادسة وما بعدها خارج التحديث.

تفاصيل القراءة والتدقيق والاختبارات والصور في [READING_V2_QA.md](docs/READING_V2_QA.md)، وإثبات حفظ الجداول السابقة في [READING_V2_INTEGRITY.json](docs/READING_V2_INTEGRITY.json). لتكرار تدقيق الحفظ، مرر **النسخة الاحتياطية التي طبعها أمر `prepare-reading` على جهازك**:

```powershell
.\.venv\Scripts\python.exe scripts/audit_reading.py --baseline "data/backups/<اسم النسخة الاحتياطية>.sqlite3"
.\.venv\Scripts\python.exe -m pytest -q tests/test_pilot_reading.py tests/test_reading_data.py
npm --prefix frontend run test:e2e -- reading-v2.spec.ts
```

نجح لهذا التحديث **198 اختبار Python و44 اختبار متصفح**. بقي المصدر والجداول الـ36 السابقة مطابقة للنسخة الاحتياطية؛ الإضافة الوحيدة في القاعدة جدول نسخة القراءة. الإبراز والتقسيم اختيارات تحريرية فحصها وكلاء، وتبقى مراجعتك لها قبل التعميم.

## تجربة أول خمس تراجم

تتوفر طبقة تحريرية مستقلة لأبي عبيدة، وطلحة، والزبير، وعبد الرحمن بن عوف، وسعد بن أبي وقاص. تحتوي عناوين موسومة «عنوان تنظيمي»، وأقوالًا وقوائم وشعرًا، وأسماء بالخمري وكلمات محورية بالبترولي مع زر تعطيل الإبراز. حُفظت **374 إشارة حاشية** في ملحق مطوي؛ لم تُعثر على متونها المقابلة في العينة. يبقى النص الخام والنسخ الحرفي والتظليل متاحًا، وتبقى الترجمة السادسة وما بعدها على العرض السابق.

بعد الاستيراد، شغّل الأمر التالي مرة واحدة، دون إعادة استيراد الكتاب أو بناء المتجهات:

```powershell
.\.venv\Scripts\python.exe -m backend.pilot prepare
```

يتحقق الأمر من المصدر والنطاقات والتغطية، ويأخذ نسخة SQLite متسقة في `data/backups/` قبل إضافة الجداول. تكراره دون تغيير يعيد `unchanged`. يرفض استبدال مسودة تغيرت بعد تسجيل قرارات بشرية؛ يلزم حينها ترحيلها مع حفظ القرارات. بيانات العينة في `reference/pilot/` مرتبطة ببصمة المصدر الحالية؛ عند اختلافها يتوقف تطبيق الطبقة ويعود القارئ إلى عرضه المعتاد.

فُحصت مقاطع العينة **1,275**، وسُجلت **239 علاقة موضوعية مقترحة** وقرارات نصية بشأن المرشحات القديمة. أُضيفت **55 تسمية مقترحة** خارج موضوعات CSV الـ81؛ بقي CSV ووسومه الأصلية محفوظين. بعض المقاطع بلا موضوع واضح، وفحص الوكيل لا يساوي اعتماد الإنسان.

من [مراجعة العينة](http://127.0.0.1:5173/pilot/reviews) تستطيع تعديل الموضوع وحدود الشاهد ثم اعتماد التوصية أو رفضها باسمك. اعتماد توصية الاستبعاد يرفض الربط القديم ويحفظ تاريخه. تبويب «تغطية المقاطع» يسجل قراءتك للمقطع مستقلًا عن اعتماد موضوعه. لم يُسجل أي اعتماد بشري باسم المستخدم أثناء التطوير.

البحث بالوصف يسترجع شواهد الفهرس الموضوعي فعليًا، إضافة إلى أفضل 100 مرشح لفظي و100 دلالي. تُدمج القنوات بـRRF دون أصوات مكررة، ويُعاد ترتيب أفضل 40 نتيجة ويُعرض عشر منها للصفحة. تتيح الشروط تفضيل الموضوع أو حصر النتائج فيه، وحصر البحث في العينة، والمعتمد بشريًا فقط. تبقى المقترحات النصية موسومة، وتُحفظ سياقات النفي والاتهام ونقد الرواية عند إزالة التداخل.

واجهات الإضافة: `GET /api/biographies/{id}/presentation` و`/topics`، و`GET /api/pilot/reviews` و`/coverage`، و`POST /api/pilot/reviews/{id}` و`/coverage/{segment_id}`. الواجهات السابقة متوافقة؛ خيارات خطة البحث الجديدة اختيارية: `topic_mode` و`pilot_only` و`reviewed_only`.

تقرير الحفظ الحرفي: [PILOT_INTEGRITY.json](docs/PILOT_INTEGRITY.json). نتائج الجودة والقيود والاختبارات: [PILOT_QA.md](docs/PILOT_QA.md). أسئلة التقييم الـ15 وشواهدها جُمّدت قبل اختبار الاسترجاع، ونتائجها تطويرية تحتاج مراجعة مستقلة؛ لا تعني توثيق الأخبار أو الأسانيد.

## الاستخدام والمراجعة

- **البحث:** النص أو العناوين أو الأعلام أو الموضوعات، جميع الكلمات أو عبارة متصلة، مع تجزئة النتائج. التطبيع للبحث فقط؛ العرض من الأصل.
- **القارئ:** قراءة منسقة افتراضيًا، وزر «النص الأصلي» يعرض النص الحرفي بعلاماته. يظلّل «اقرأ السياق» النطاق نفسه في الوضعين، وتُحفظ أفضلية العرض محليًا. يمكن نسخ النص المنسق مع مرجعه أو الأصل الحرفي. النطاقات نصف مفتوحة `[start,end)` بوحدات Unicode، وليست بايتات أو وحدات UTF-16.
- **الأعلام:** هوية مستقلة لكل صاحب ترجمة، مع فصل ترجمته عن مواضع الذكر المرشحة. الأسماء المتشابهة لا تُدمج تلقائيًا.
- **الموضوعات:** جميع موضوعات CSV البالغ عددها 81 في 9 أبواب؛ لكل مطابقة مقطع حاضن وشاهد حرفي ونطاق وطريقة اكتشاف وحالة مراجعة. يمكن عرض الفقرة الحاضنة وفتح الأصل.
- **المراجعة:** اعتماد/رفض/تعديل الوسم أو هوية المذكور، وتعديل حدود المقطع ونوعه، مع اسم المراجع وملاحظة وسجل قبل/بعد. تُرفض الحدود التي تخرج من الأصل أو تستبعد شواهد مرتبطة.
- **ربط يدوي:** من القارئ اختر «استعراض المقاطع وحدودها» ثم «ربط بموضوع». اختر الموضوع وحدود الشاهد والمراجع. يُستخرج النص من الأصل، والوضع الابتدائي مرشّح.

`keyword_candidate` اقتراح لفظي، و`semantic_candidate` نتيجة استرجاع دلالي مرشحة، و`manual` إضافة يدوية. حالة `reviewed` مستقلة عن طريقة الاكتشاف؛ اعتماد اقتراح لفظي لا يغير تاريخ اكتشافه. البحث الدلالي لا يكتب وسومًا أو يعتمد هويات. الوسم يخص مقطع الدليل ولا ينسحب على جميع فقرات الترجمة.

## البحث بالوصف محليًا

اختر «بحث بالوصف»، واكتب ما تريده، ثم اضغط «اقترح المعاني». يعرض المحلل المحلي احتمالًا إلى ثلاثة احتمالات دون اقتباسات أو أعداد نتائج. اختر المعنى، وعدّل وصفه والمفاهيم والألفاظ المساعدة أو الشروط، ثم اضغط «ابحث بهذا المعنى».

- **الألفاظ المساعدة والمفاهيم** توسّع البحث ولا تُلزم ورودها كلها.
- **الكلمات المطلوبة** شروط لفظية يلزم ورود جميع عباراتها في النافذة؛ **المستبعدة** تمنع أي عبارة منها. افصل العبارات بفاصلة عربية أو إنجليزية. التطبيع للبحث فقط.
- الشروط المتعلقة بالنفي أو الأفعال أو الأشخاص تبقى محتاجة إلى قراءة السياق؛ تشابه المعنى ليس تحقيقًا علميًا. التحليل قواعد معلنة ومعجم مساعد، وليس نموذج محادثة يفهم كل صياغة.
- النتائج أفضل المقاطع المرشحة، لا حصر لجميع مواضع الكتاب. تُزال النوافذ المتداخلة المتكررة دون دمج الأشخاص، ويُعرض مصدر كل شاهد ونطاقه.

المتطلبات الدلالية **اختيارية** وتحتاج Python 3.12 أو أحدث مع الإصدارات المثبتة هنا؛ البحث اللفظي والقارئ يعملان دونها. داخل البيئة نفسها التي تشغّل الخادم:

```

لنسخة CPU الأسرع التي جُهزت في هذا المشروع، استخدم ملفات ONNX المكممة الرسمية للنموذجين المثبتين:

```

الأمر الثاني يستخدم النماذج المنزلة دون شبكة ويستأنف العمل. بعد الإعداد لا يستخدم البحث الشبكة. تبقى ملفات الأصل والمراجعات دون تعديل؛ النوافذ والفهارس المشتقة في `data/semantic/` والنماذج في `data/models/`. قد يُحذف الفهرس المشتق ويعاد بناؤه، لكن لا تحذف قاعدة المراجعات.

إذا انقطع النظام قسرًا وبقي `prepare.lock` أو `paragraphs-prepare.lock`، لا تزيله قبل التأكد من انتهاء عملية الإعداد التي يسجل رقمها؛ القفل يحمي من بناء نسختين معًا. الانقطاع العادي يزيله تلقائيًا. تُحفظ دفعات الترميز بترتيب ثابت حسب الطول لتقليل الحشو الحسابي، مع كتابة كل متجه عند معرّف نافذته الأصلي والتحقق من جميع المتجهات قبل النشر.

تُجمع فقرات متجاورة داخل القسم نفسه حتى 320 رمزًا لغويًا، مع تداخل يصل إلى 64 رمزًا عند حدود الفقرات؛ الفقرة الطويلة وحدها تُجزّأ بنطاقات أصلية. يبني أمر الإعداد أيضًا فهرسًا مستقلًا لجميع الفقرات كي لا تضيع دلالة القول القصير داخل سياق طويل. يجمع الاسترجاع أفضل 100 مرشح لفظي و100 دلالي باستخدام RRF؛ وعند اكتمال المستويين تُوزع الحصة الدلالية على 50 نافذة سياقية و50 فقرة، مع دمج رتبتيهما بالتناوب. ثم يعيد ترتيب أفضل 40، في صفحات من 10 نتائج. عامل استدلال منفصل واحد يستخدم أربعة خيوط CPU. تُحفظ نتائج الطلب 15 دقيقة لتثبيت صفحات العرض، وتبطل عند تغيّر الفهرس أو المراجعات. تتضمن حالة الفهرس حالة الفقرات وتغطيتها؛ إن غاب المستوى الإضافي بقي الفهرس السياقي المكتمل متاحًا. تعديل حدود المقاطع بالمراجعة يجعل فهرس الفقرات قديمًا حتى إعادة الإعداد، دون إبطال المصدر.

عند غياب النماذج أو قدم الفهرس أو فشل الاستدلال، تُظهر الواجهة السبب وتعرض البحث اللفظي فقط بدل ادعاء بحث دلالي. لتعطيل الاستدلال محليًا يمكن تعيين `$env:SIYAR_SEMANTIC_DISABLED = '1'`. لا يُنزّل أي نموذج أثناء البحث.

واجهات الإضافة: `GET /api/biographies/{id}/reading-view` و`GET /api/sections/{id}/reading-view` وقراءة مقتطف مصدر، و`POST /api/search/interpret` و`POST /api/search/smart` و`GET /api/semantic/status`. تبقى واجهات الأصل والبحث اللفظي متوافقة. في خطة البحث `expansion_terms` ألفاظ مساعدة، و`include_terms` شروط مطلوبة، و`exclude_terms` مستبعدة، و`topic_ids` مفاهيم مساعدة؛ `meaning` الوصف الذي اختاره المستخدم.

## حالة النسخة وحدودها

الاستيراد الحقيقي: **5,943 ترجمة، 5,933 هوية مرشحة، 129,006 مقاطع، 19,869 مطابقة موضوعية، 46,642 موضع ذكر، 14,045 علامة صفحة**. جميع النتائج الآلية غير معتمدة بشريًا. حُفظت محارف المصدر البالغ عددها **12,665,488** كاملة، بما فيها الميتاداتا والسيرة والأقسام والخواتيم. تضم `source_sections` عدد 6,290 قطعة متجاورة: التراجم والأقسام وقطعة الميتاداتا؛ ليست 6,290 ترجمة.

توجد 1,264 علامة `PageV00P000` غير صالحة كإحالة محددة. وثائق النسخة الرسمية تنبه إلى اضطراب ترقيم الأجزاء الثلاثة الأولى ونقص في مواضع `PageV01P376` و`PageV01P385`. تعرض الواجهة **علامات OpenITI الخام غير المحققة طباعيًا**. لا توجد سنوات وفاة مستنتجة.

المطابقة محافظة على حدود الكلمات؛ لا يوجد تحليل صرفي أو حل آلي للضمائر. قد تفوتها اللواصق واختصارات الأسماء وأشكالها غير المفهرسة. يُستبعد لفظ «النار» وحده من اقتراح موضوع أخروي لالتباس دلالته. لا توجد دعوى بفهرسة كل موضوع أو استخراج كل قصة أو كل موضع ذكر.
