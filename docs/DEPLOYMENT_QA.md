## عائق GHCR والإجراء المتخذ

بلغ الإصدار نشر الصور بعد نجاح اختبارات التطبيق، لكن GitHub أعاد خصوصية `public` للحزمتين وأكد السحب المجهول توفرهما. أوقف الحارس إنشاء `production`، ثم [سُحبت الحزمتان](https://github.com/M-Jadallah/Sear-Alaam-Anobalaa/actions/runs/40901159998) بعد فحص ملكية المستودع وأن النسخ تخص الإصدار المرفوض وحده. أصبح السحب المجهول مرفوضًا بالرمز 403 لكليهما.

أُجري [اختبار إنشاء بصورة فارغة](https://github.com/M-Jadallah/Sear-Alaam-Anobalaa/actions/runs/40901589639)، بلا شيفرة التطبيق أو المصدر أو قاعدة البيانات. أُنشئت الحزمة الجديدة عامة أيضًا وسُحبت تلقائيًا. **لا توجد صور خاصة معتمدة أو digests قابلة للنشر في production حاليًا.** معرفات الصور في التقرير هي معرفات الصور المختبرة قبل سحبها.

يشترط حارس النشر الآن وجود الحزمتين بخصوصية `private` قبل رفع أي بيانات تطبيق؛ غياب الحزمة لم يعد يسمح بتجربة الرفع الفعلي. يعيد فحص الخصوصية قبل الدفع وبعده. نجحت اختبارات رفض الحزم العامة والمفقودة وأخطاء الصلاحيات. لا تُلغى بوابة الخصوصية لتجاوز العائق.

أظهر GitHub API أن مستودع الشيفرة الحالي عام؛ لم يُغيَّر إعداد رؤيته. بيانات دخول المدير لا تدخل الصور أو المستودع وتُحقن وقت التشغيل. توثق GitHub [إدارة رؤية الحزم](https://docs.github.com/en/packages/learn-github-packages/configuring-a-packages-access-control-and-visibility) و[واجهات Packages](https://docs.github.com/en/rest/packages/packages). يلزم الوصول لإعدادات GitHub لمعالجة إنشاء الحزم الخاصة؛ التحكم المحلي بالمتصفح معطل، والاعتماد المحلي لا يملك صلاحية قراءة Packages.

## ما بقي على VPS

لم يُنشر التطبيق على VPS. فحص `/api/live` عبر HTTP أعاد 404، وفشل تحقق HTTPS بسبب شهادة ذاتية. لا يوجد اتصال SSH مُعد محليًا أو وصول متاح إلى Coolify.

بعد معالجة خصوصية GHCR: إعادة تشغيل الإصدار، والتحقق من الصور الخاصة وdigests وفرع production، ثم ربطه بCoolify وإدخال بيانات المدير وصلاحية السحب. يلزم قياس هامش RAM ≥200MiB مع Coolify، وعدم OOM وإعادة التشغيل، وp95 ≤30 ثانية على VPS نفسه، واختبار ازدحام البحث وHTTPS وروابط القارئ وإعادة تشغيل VPS والرجوع. لا يحل نجاح CI محل هذه القياسات.
