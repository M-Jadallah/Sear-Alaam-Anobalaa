## 2) نموذج البيانات المطلوب
1. `sources`: إصدار النص، بصمة SHA-256، مرجع URL، بيانات الترخيص إن أمكن تثبيتها.
2. `page_markers`: علامات الأجزاء/الصفحات ونطاقاتها المعتمدة بعد فحص المصدر.
3. `biographies`: عنوان الترجمة كما في المصدر، النص الكامل بلا اختزال، موضع البدء والنهاية، صفحات البداية والنهاية، حالة الاستخراج، صاحب الترجمة إن أمكن تحديده.
4. `people` و`person_aliases`: هوية العلم وأشكال اسمه. ربط الأسماء المتشابهة لا يُحسم تلقائيًا.
5. `person_mentions`: مواضع ذكر الأعلام داخل تراجم غيرهم مع سياق حرفي ونطاق دقيق وحالة مراجعة؛ إظهار الأشخاص المذكورين بعد الترجمة الأساسية عند فتح بطاقة علم.
6. `segments`: فقرات نصية أو أقوال أو أخبار/قصص مع نطاق نصي دقيق في المصدر، ونوع المقطع وحالة مراجعته.
7. `topics`: شجرة التصنيفات وتسميات الموضوعات والألفاظ المستوردة من CSV.
8. `topic_hits`: علاقة الموضوع بمقطع محدد؛ شاهد حرفي ونطاق، وطريقة الاكتشاف (`keyword_candidate`, `semantic_candidate`, `reviewed`) وحالة المراجعة.
9. `review_log`: ما تغير ومن غيّره وتاريخ التغيير.

عند بداية المشروع خذ `db/schema.sql` مخططًا مرجعيًا يمكن تطويره بالمهاجرات، ولا تتعامل معه كعقد لا يقبل التحسين.

## 3) شاشات التطبيق
- الصفحة الرئيسية: أرقام المصادر والتراجم والموضوعات والمواضع المراجعة وغير المراجعة.
- التصنيفات: الأبواب التسعة مع موضوعاتها، عدد نتائج كل موضوع، تصفية حسب حالة التحقق.
- صفحة الموضوع: **مقاطع الأدلة**، عنوان الترجمة المستضيفة، صاحبها، علامة الجزء/الصفحة إن تأكدت، زر «اقرأ السياق».
- صفحة الأعلام: البحث بالاسم والكنية واللقب، تمييز الأشخاص المختلفين المتشابهين في الاسم.
- صفحة الشخصية: (أ) نص ترجمتها الكامل أو تراجمها المعتمدة، (ب) جميع مواضع ذكرها في سائر الكتاب التي جرى استخراجها ومراجعتها؛ لا تساوِ آليًا بين اللفظ والهوية.
- قارئ النص: قراءة كاملة مع تظليل موضع الاستشهاد وإظهار الترقيم المرجعي ومسار المصدر.
- لوحة مراجعة: اعتماد/رفض/تعديل الوسم، تعيين هوية علم، تحرير حدود مقطع مع إبقاء الأصل محفوظًا.
- البحث العام: بحث تقليدي بالعبارات والكلمات مع اختيارات بحث داخل العناوين/النص/الأعلام/الموضوعات.

## 4) مراحل استخراج البيانات
- المرحلة أ: قراءة الملف الآمن، اكتشاف الخطابات/الميتاداتا والعناوين/الصفحات بأمثلة حقيقية، توثيق افتراضات Parser.
- المرحلة ب: تقسيم إلى تراجم باستخدام علامات موثوقة، وتسجيل كامل النص ونطاقات Unicode الأصلية والصفحات بلا تخمين.
- المرحلة ج: التقسيم إلى فقرات ومقاطع، البحث العربي المطبع، وسوم اقتراحية على مستوى الشاهد؛ تأكيد الدقة بمقارنة المقطع بالنص الأصلي.
- المرحلة د: استخراج الأعلام المذكورين والكنى والصفات وعلاقات الرواية، مع حفظ درجة الثقة والمراجعة اليدوية، لا إزالة الالتباس القسري.
- المرحلة هـ: اقتراح وسوم بالمعنى باختيار المستخدم (إن توفرت بيئة AI)، مع الإلزام بشاهد نصي حرفي صالح ومراجعة يدوية.

## 5) محرك البحث والفهرسة
- استخدم SQLite FTS5 أو فهرسًا مكافئًا مع `normalized_search_text` مشتقًا من الأصل.
- يمكن إزالة التشكيل وتوحيد أشكال الألف والياء لأغراض البحث، لكن النص المعروض يبقى حرفيًا، واحذر التطبيع المفرط في أسماء الأعلام.
- طبّق تجزئة نتائج البحث، والترتيب حسب ملاءمة النص، وروابط العودة للمواضع.
- يظهر نوع المطابقة ومستوى الثقة لكل نتيجة. في حالة عدم وجود نتيجة، لا تدّعِ غياب الموضوع عن الكتاب كله.

## 6) قاعدة الدقة والتوثيق

### التشكيل التحريري الاختياري في القارئ

تضيف دفعات التحرير الجديدة الحركات في طبقة مشتقة مرتبطة ببصمة المصدر ومواضع Unicode صفرية العرض، دون تعديل الحروف أو حركات الأصل أو المقاطع أو نصوص الأدلة. يوضح القارئ أن الضبط أضافه الوكيل، ويتيح تعطيل إضافاته مع بقاء ضبط المصدر، ويبين الكلمات الملتبسة. يظل وضع الأصل والنسخ الخام وشواهد البحث حرفية. النسخ المنسق يتبع وضع العرض ويشمل المرجع والتنبيه؛ لا ينسب الضبط التحريري إلى المصدر. صحة الإعراب تحتاج مراجعة لغوية مستقلة، ولا تثبتها عدادات الحركات.

- كل اقتباس معروض موجود حرفيًا في المصدر الأصلي وقابل للتحقق من موضعه.
- لا توثق الجزء/الصفحة إن كانت فقط أقرب علامة سياقية دون تحقق؛ أعرض `غير محقق` أو علامة OpenITI مع وصف واضح.
- تحقق من قاعدة وقوع علامات `PageV...P...` بالنسبة لنص الصفحة قبل تحويلها إلى إحالات مطبوعة.
- لا يوجد ضمان لفهرسة «جميع» موضوعات الكتاب إلا بعد تحقيق الشمول ومراجعة النتائج.
- المؤلف/الراوي/المقول عنه/صاحب الترجمة أدوار مختلفة، ولا ينسب القول إلى الذهبي تلقائيًا.

## 7) واجهات API المقترحة
- GET `/api/categories` وGET `/api/topics?category_id=`
- GET `/api/topics/{id}/evidence?status=`
- GET `/api/people?q=` وGET `/api/people/{id}`
- GET `/api/people/{id}/mentions`
- GET `/api/biographies/{id}` وGET `/api/biographies/{id}/segments`
- GET `/api/search?q=&scope=`
- GET `/api/stats` وPOST `/api/reviews/topic-hits/{id}`
- أمر CLI محلي `import_book` لاستيراد `data/source.mARkdown` قابل لإعادة التنفيذ دون تكرار السجلات.

## 8) التقنيات، التشغيل، والأمان
ابدأ محليًا FastAPI + SQLite FTS5 + React/TypeScript. تجنب البنية الموزعة المبكرة. أضف وثائق نسخة Python/Node والأوامر الدقيقة، مع نسخ احتياطي ومهاجرات SQLite وقواعد مرور في واجهة إدارة المحتوى إذا نشرت للعامة.

## 9) الحقوق والنشر
المستودع متاح علنًا لا يعني تلقائيًا إذن نشر غير محدود: قبل النشر العام اعرض بيانات المصدر والتحقيق وراجع شروط وحقوق النص والطبعة.
